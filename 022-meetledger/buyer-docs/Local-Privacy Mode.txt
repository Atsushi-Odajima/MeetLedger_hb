MeetLedger Local-Privacy Mode（外部に送らない使い方）
====================================================

MeetLedger は「ローカル優先（Local-first）」で作られています。初期設定のままなら、会議の音声・
文字起こし・AI 処理は、お客様のサーバー（またはデスクトップアプリのパソコン）の中だけで行われます。
この文書では、その仕組みと、外部サービスを使う場合の設定、確認の方法を説明します。

※ 「Local-Privacy Mode」という名前のスイッチがあるわけではありません。以下の初期設定の組み合わせのことです。


1. 初期設定（何もしなければこうなります）
----------------------------------------------------

  文字起こし             ローカル（sherpa-onnx SenseVoice）。音声はサーバーの外へ送りません
  AI 処理（要約・抽出・質問） ローカルのルール（local-rules）。外部へ送りません
  AI 検索用データ        ローカル（local-hash）。外部へ送りません
  メール                 送信しない（アプリ内の通知だけ。EMAIL_DRIVER=outbox）
  ファイルの保存         サーバーのディスクに暗号化して保存（AES-256-GCM）
  音声の保存期間         処理が終わるまで（文字起こしが成功したら削除）

  セットアップ画面の「初期設定はローカル優先です」のとおり、管理者が明示的に許可するまで、
  外部のサービスへ会議の内容は送られません。
  開発時のテストでも、ローカル設定での文字起こしで外部への通信が 0 件であることを確認しています。


2. クラウドを使うには「二重の許可」が必要
----------------------------------------------------

  外部の文字起こし・AI サービスに会議の内容を送るには、次の両方が必要です。

    (1) サーバーの設定（.env。サーバー管理者）
          CLOUD_TRANSCRIPTION_PROVIDER = openai / deepgram（none ならクラウド文字起こしは使えません）
          AI_PROVIDER                  = openai / anthropic（local-rules ならクラウド AI は使えません）
          EMBEDDING_PROVIDER           = openai（local-hash なら AI 検索用データを外部へ送りません）
          と、それぞれの API キー
    (2) Workspace 管理者の許可（画面）
          「設定」→「プライバシー」→「クラウド処理の許可」
            クラウド文字起こしを許可 / AIの処理方法 / クラウドAIを許可 / AI検索（Embedding）の方法

  さらに、会議ごとの設定（文字起こしの方法、AI 処理の ON/OFF、機密）が優先されます。
  許可していない場合、クラウド AI を選んでいてもローカルのルールで処理されます。

  自社サーバーの AI（Ollama）について
    - サーバーの設定（AI_PROVIDER=ollama、AI 検索用データにも使う場合は EMBEDDING_PROVIDER=ollama）で有効にした
      場合だけ、Workspace 管理者が「AIの処理方法」「AI検索（Embedding）の方法」で「Ollama（自社サーバー）」を選べます
      （クラウドの許可は不要です）。有効でない場合は、選んでもローカルのルール / local-hash で処理されます。
    - 文字起こしの抜粋は OLLAMA_URL（標準: 同じサーバーの http://127.0.0.1:11434）の Ollama へ送られます。
      送信先は、同じサーバー（127.0.0.1 など）か OLLAMA_URL のホストに限られ、送信の記録が残ります。
    - OLLAMA_URL を別のサーバーにしている場合、データはそのサーバーへ送られます。Ollama を置くサーバーの管理も、
      お客様の責任で行ってください。


3. 会議ごとに守る
----------------------------------------------------

  会議の作成時、または会議の「設定」タブ →「プライバシーと処理」で設定します。

  AI処理（要約・抽出・質問）を OFF
    - その会議は、ローカル・クラウドを問わず、どの AI にも渡されません。
    - AI 検索用データは作られず、OFF にした時点で削除されます。
    - 手動の記録と、言葉での検索（全文検索）は使えます。

  機密（Confidential）プリセット
    - AI 処理 OFF、クラウド文字起こし不可（ローカルに変更）、音声は処理後すぐ削除（保存しない／処理が終わるまで）、
      Workspace 全体には公開しない、をまとめて設定します。
    - 機密の会議の内容を Slack などの外部へ送る依頼をするときは、追加の確認が求められます。

  公開範囲
    - 「自分だけ（Private）」は作成者だけが見られます。管理者も見られず、検索・AI の回答・通知・
      書き出しにも出ません。

  文字起こししない（メモのみ）
    - 録音も文字起こしも行わず、手動メモで記録します。


4. 「どこに何が送られるか」を確認する
----------------------------------------------------

  「設定」→「プライバシー」の上部に「どこに何が送られるか」が表示されます。
    データ（会議の音声 / 文字起こし・メモの抜粋 / AI 検索用データ / 通知メール / ファイルの保存）ごとに、
    「このサーバー内」か「外部サービス」か、どのサービスかを示します。
  - 閲覧できる会議のうち、AI 処理の対象・AI OFF・機密・クラウド文字起こしの件数
  - 「外部に送られないもの」の一覧
  - 「送信内容のプレビュー（詳細）」: どの項目が・どのくらいの量で送られるか（本文は表示しません）
  - 画面下部に、このインストールで使える設定（クラウド文字起こし / AI / Embedding）が表示されます。

  外部への送信は、送る直前にもう一度、会議の AI OFF・機密・ローカル設定をデータベースで確認してから行われ、
  送信の記録（日時・種類・送信先・データ量。内容は含みません）がサーバーに残ります。


5. ローカルでも外部と通信する場面
----------------------------------------------------

  次の場合は、会議の内容とは別に（または管理者・利用者が設定・承認した範囲で）外部と通信します。
    - 文字起こしモデルのダウンロード（管理者・利用者が明示的に操作したときだけ。会議の内容は送りません）
    - カレンダー連携・ICS の購読 URL（設定した場合のみ。予定を読み取るだけ）
    - メール送信（EMAIL_DRIVER=smtp に設定した場合のみ。通知メールに会議の発言は含めません）
    - Slack・Gmail（下書き）・HubSpot・Webhook への送信（人が内容を確認して承認した場合のみ）
    - 送信 Webhook（設定した場合のみ。ID などの最小限の情報。文字起こし・メモ・AI の出力は含めません）
    - MCP / API トークンで接続した AI アシスタント（トークンを発行した場合のみ。アシスタント側にデータが渡ります）


6. デスクトップアプリのローカルモード
----------------------------------------------------

  - 「この端末で文字起こし（音声は送信しない／テキストのみ送信）」を選ぶと、パソコンの中で文字起こしを行い、
    サーバーには文字・時刻・話者ラベルだけを送ります。
  - 「音声もアップロード」をオンにした場合や「音声をサーバーへアップロード」を選んだ場合だけ、音声を
    MeetLedger のサーバーへ送ります（外部の文字起こしサービスへ送るわけではありません）。
  - 作業用の録音ファイルはパソコンに保存され、送信・アップロード後に削除されます。設定画面の
    「録音ファイルをすべて削除」でまとめて削除できます。


7. 「ローカルだから完全に安全」ではありません
----------------------------------------------------

  ローカル優先は「外部の AI 事業者にデータを渡さない」ための設計です。サーバーやパソコンそのものの管理は
  お客様の責任です。
    - OS・ソフトウェアの更新、ディスクの暗号化、アクセス権の管理
    - データベースのデータ（文字起こし・メモなど）は、データベースの中では暗号化されていません。
      データベースのディスク暗号化や、アクセスできる人の限定を行ってください。
    - バックアップファイルの暗号化と保管、暗号鍵（MASTER_KEY）の保管（「Backup-Restore.txt」）
    - 退職者のアカウント削除、管理者アカウントの保護


8. クラウドを許可する前に
----------------------------------------------------

  1) 送信先（OpenAI / Anthropic / Deepgram など）との契約内容（データの学習への利用、保存期間、処理する国・地域）を
     確認してください。
  2) 個人情報を外国の事業者に送ることになる場合の扱い（同意の取得など）を、法務担当者と確認してください
     （参考: docs/PRIVACY_CONSENT.md 5 章。法的助言ではありません）。
  3) 参加者への通知文に、送信先を書いてください（「録音と同意.txt」8 章）。
  4) 費用の目安を確認してください（「運用コスト.txt」）。
  5) 本製品のクラウド連携は、実際の各社 API での接続確認をしていません（未検証）。試験環境で確認してから
     本番で有効にしてください。
