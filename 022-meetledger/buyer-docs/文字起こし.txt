MeetLedger 文字起こしガイド
====================================================

文字起こし（音声を文字にすること）の方法、精度の目安、聞き取れなかった部分の扱い、
話者の名前の付け方、誤りの直し方をまとめています。


1. 文字起こしの方法
----------------------------------------------------

  会議ごとに「プライバシーと処理」の「文字起こし」で選びます。

  ローカル文字起こし（Local）  標準。音声はこのサーバー内で処理され、外部へ送信されません。
  クラウド文字起こし（Cloud）  外部の文字起こしサービス（OpenAI または Deepgram）へ音声を送ります。
                               サーバーの設定と、Workspace 管理者の許可の両方が必要です（10 章）。
  文字起こししない（メモのみ） 録音・文字起こしは行わず、手動メモで記録します。

  このほか、
    - デスクトップアプリの「この端末で文字起こし」: パソコンの中で文字起こしし、文字だけをサーバーへ送ります
      （音声は送りません）。
    - 文字起こしファイルの取り込み: 会議ツールが出力した SRT / VTT / TXT / JSON を取り込みます（9 章）。


2. ローカル文字起こしのしくみ
----------------------------------------------------

  - 文字起こしエンジン: sherpa-onnx（オープンソース）＋ SenseVoiceSmall モデル（日本語・英語に対応）
  - 音声区間の検出: Silero VAD
  - 話者分離（誰が話したかの区別。任意）: pyannote segmentation-3.0 ＋ 3D-Speaker CAM++
  - モデルは管理者が「bash scripts/download-models.sh」で取得します（「はじめに.txt」6 章）。
    話者分離のモデルが無い場合は、文字起こしだけを行います。
  - 処理はすべてサーバー（またはデスクトップアプリのパソコン）の CPU で行い、文字起こしのために
    外部サービスへ通信しません。
  - モデルのライセンス: SenseVoiceSmall は出典表示が必要、3D-Speaker CAM++ は商用利用のライセンスが
    未確認です（「設定」→「このアプリについて・ライセンス」、「THIRD_PARTY_NOTICES.txt」1 章）。


3. 速度と精度の目安
----------------------------------------------------

  速度（2026-10-02、開発環境での実測。Intel Xeon 4 vCPU / メモリ 15GB）
    - 文字起こしのみ: 音声の長さの約 0.12 倍の時間（RTF ≈ 0.12）
    - 話者分離あり:   音声の長さの約 0.21 倍の時間（RTF ≈ 0.21）
      → 1 時間の会議で、およそ 7〜13 分の処理時間
    - 初回はモデルの読み込みに 1〜2 秒かかります。

  精度
    - 測定に使ったのは、モデルに付属するクリアな朗読音声です。それでも 1 文に 1 語程度の誤りがありました
      （例: 「持っていけない」→「持っていきない」、英語の "gold" → "code"）。同じ音声でも、区切り方によって
      結果が少し変わることがあります。
    - 実際の会議音声（雑音、話し声の重なり、専門用語、遠いマイク）での精度は測定していません（未測定）。
    - 日本語の会議での話者分離の精度も評価していません。話者分離のモデルは中国語・英語中心のデータで
      学習されています。
    → 文字起こしは「人が確認する前提の下書き」とお考えください。重要な内容は必ず音声や参加者に確認してください。

  クラウド文字起こしの精度も、日本語の会議では確認していません（未検証）。


4. 対応する音声・動画ファイル
----------------------------------------------------

  WAV、MP3、M4A / MP4 / MOV / AAC、WebM / MKV、Ogg / Opus、FLAC
  - 1 ファイルの上限は、サーバー設定 MAX_UPLOAD_MB（標準 1024MB）です。
  - ファイルの中身（形式）を確認し、音声が入っていないファイルや形式の合わないファイルは受け付けません。
  - 同じ会議に同じファイルをもう一度アップロードしても、二重には処理されません。


5. 聞き取れなかった部分
----------------------------------------------------

  - 音声から聞き取れなかった部分は「［聞き取れず］」と表示されます。
  - AI やルールで推測して埋めることはしません。要約や候補の抽出でも、聞き取れなかった部分は補いません。
  - 「認識の確度が低い箇所」は色を変えて表示します（クラウド文字起こしや取り込みファイルで確度の情報が
    ある場合のみ。ローカル文字起こしは確度の情報を返さないため表示されません）。
  - 文字が変わるのは、人が発言を編集したときだけです（6 章）。


6. 話者（誰が話したか）
----------------------------------------------------

  - 話者は「Speaker 1」「Speaker 2」のような匿名のラベルで表示されます。
  - MeetLedger は声から人物を特定しません（声の特徴の登録・照合の機能はありません）。
  - 名前の付け方:
      1) 「文字起こし（Transcript）」タブの「話者」に並ぶラベルを押します。
      2) 「表示名」を入力するか、「人（People）と対応づける」で登録済みの人を選び、保存します。
    確認待ち（Review Inbox）の「話者・参加者」タブからも設定できます。
  - 「候補あり」の表示: 2 チャンネルの録音（デスクトップアプリ）では、音の大きさから
    「あなた（マイク）」「相手側（システム音声）」という候補が出ることがあります。
    候補は自動では適用されません。内容を確認して「この候補を入力」→ 保存してください。
    ヘッドホンなしで相手の声がマイクに入ると、候補が誤ることがあります。
  - デスクトップアプリの「この端末で文字起こし」では、マイクとシステム音声の大きさから、話者が
    「あなた」「相手」（話者分離を使うと「相手1」「相手2」…）と表示されます。判定できない部分は
    「話者N」や「不明」になります。システム音声を録音していない場合は「あなた」とは判定しません。
  - 話者の名前を設定したあと、「候補を抽出し直す」が表示された場合は、押すとまだ確認していない候補を
    新しい名前で抽出し直します（確認・編集済みの項目はそのまま残ります）。


7. 文字起こしを直す
----------------------------------------------------

  1) 発言の横にある編集ボタン（マウスを重ねると「編集」と表示されます）を押します。
  2) 「発言内容」や「話者」を直して「保存」します。
  3) 変更は「編集履歴」（発言の横の履歴ボタン）に残ります（元の文も確認できます）。
  - ほかの人が先に同じ発言を編集していた場合は、上書きせずに「ほかの人が先に編集しました」と表示されます。
    「サーバーの内容を使う」か「確認したうえで自分の編集を保存」を選んでください。
  - 決まったこと・やることなどの根拠になった発言を編集すると、台帳では「元の発言は編集されています」と表示されます。


8. 探す・聞き直す
----------------------------------------------------

  - 「文字起こし内を検索」で、この会議の発言を検索できます。
  - 「会議の音声」で再生できます（音声の保存期間内のみ）。発言の時刻を押すと、その位置から再生します。
  - 再生できない場合は、保存期間の設定により音声が削除された可能性があります。
  - 「バージョン」で、以前の文字起こし（やり直す前のもの）を表示できます。


9. 文字起こしファイルを取り込む
----------------------------------------------------

  「記録（Capture）」タブ →「文字起こしを取り込む（SRT / VTT / TXT）」
    - ファイルを選ぶか、内容を貼り付けます（5MB まで）。形式は自動判定されます（SRT / WebVTT / テキスト / JSON）。
    - 「名前: 発言」の形の行や、VTT の話者タグは話者名として取り込みます（ファイルに書かれた名前です）。
    - 時刻の無いテキストは、時刻を作らずに取り込みます。
    - 取り込んだ内容は、AI 処理が ON の会議では候補の抽出の対象になります。


10. クラウド文字起こしを使う場合
----------------------------------------------------

  必要な設定（両方とも必要です）
    (1) サーバーの設定（.env）: CLOUD_TRANSCRIPTION_PROVIDER=openai または deepgram と、その API キー
    (2) Workspace 管理者の許可: 「設定」→「プライバシー」→「クラウド文字起こしを許可」
  そのうえで、会議ごとに「クラウド文字起こし（Cloud）」を選びます。

  送るもの / 送らないもの
    - 送るもの: 会議の音声（16kHz モノラルに変換したもの。映像は除きます）、言語の指定
    - 送らないもの: 会議のタイトル、参加者名、メモ、元のファイル名
    - 送信の記録（日時・送信先・データ量。内容は含みません）がサーバーに残ります。

  注意
    - 機密（Confidential）の会議では使えません。
    - 許可がない・設定がない場合、ローカルへ自動で切り替えることはしません（選択を勝手に変えないため）。
      会議の設定を「ローカル文字起こし（Local）」に変えて、「文字起こしをやり直す」を押してください。
    - OpenAI は 1 回に送れるファイルが約 25MB までです。超える場合は自動で圧縮し、それでも超える場合は
      エラーになります（長い会議はローカル文字起こしをお使いください）。
    - OpenAI の gpt-4o 系の文字起こしモデル（標準設定の gpt-4o-transcribe-diarize を含む）は、
      2027-02-26 に提供終了と告知されています（2026-10-02 時点の調査）。後継モデルでの動作・話者分離は
      未確認です。
    - 実際の OpenAI / Deepgram の API への接続は、開発時に確認していません（未検証）。


11. うまくいかないとき
----------------------------------------------------

  - 「処理の状況」に「ローカル文字起こしを実行できません」: 文字起こしモデルが入っていません。
    管理者に「はじめに.txt」6 章の作業を依頼し、そのあと「文字起こしをやり直す」を押してください。
  - アップロードできない: ファイルの大きさ（MAX_UPLOAD_MB）、形式、会議の設定が
    「文字起こししない（メモのみ）」になっていないかを確認してください。
  - 話者が分かれない: 話者分離のモデルが入っていない可能性があります（文字起こしは行われます）。
  - 同じ音声で「文字起こしをやり直す」を押しても、同じ方法で処理済みなら新しい版は作られません
    （同じ結果を二重に作らないため）。方法（ローカル / クラウド）を変えた場合は新しい版になります。
