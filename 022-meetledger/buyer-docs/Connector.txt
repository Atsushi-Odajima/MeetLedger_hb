MeetLedger 連携ガイド（カレンダー / 外部送信 / Webhook / API トークン / ChatGPT・Codex）
=====================================================================================
対象バージョン: MeetLedger 1.0（2026-10-02 時点）
技術詳細: docs/CONNECTORS.md、docs/MCP_PLUGIN.md

■ 最初にお読みください（検証状況）
- 本製品の連携機能は、各サービスの公開仕様に基づいて実装し、模擬応答による自動テストで動作を確認しています。
- 開発時点では Google / Microsoft / Slack / HubSpot / Gmail / ChatGPT / Codex の実アカウントでの接続確認は行っていません（未検証）。
  本番利用の前に、お客様の環境で各サービスとの接続を必ずご確認ください。
- 連携を使わなくても MeetLedger は利用できます（会議の手動作成・.ics ファイル取り込み）。
- 本書の画面名（「設定 → コネクタ」等）は 2026-10-02 時点の Web アプリの日本語表示です。同じ操作は REST API
  （docs/CONNECTORS.md §1）でも行えます。

--------------------------------------------------------------------------
1. 基本方針
--------------------------------------------------------------------------
- カレンダーは「読み取り専用」です。MeetLedger がカレンダーに予定を書き込むことはありません。
- カレンダーの予定は、まず「プレビュー」として表示されます。会議（Meeting）として登録されるのは、
  利用者が選んで「{n}件を取り込む」を押した予定だけです。同じ予定を何度取り込んでも重複しません。
- Slack・メール・CRM など外部への書き込みは、必ず「プレビュー → 人による承認」を経てから 1 回だけ実行されます。
  承認は Web 画面からのみ可能で、API トークンや AI アシスタント（ChatGPT / Codex 等）からは承認できません。
- 連携サービスのトークン・パスワード類は暗号化して保存し、画面や API に再表示しません。

--------------------------------------------------------------------------
2. カレンダー連携
--------------------------------------------------------------------------
2-1. Google カレンダー（管理者の事前準備）
  1) Google Cloud Console で OAuth クライアント（ウェブアプリケーション）を作成します。
  2) 承認済みリダイレクト URI に次を登録します:
       https://<MeetLedger のドメイン>/api/connectors/oauth/callback
  3) Google Calendar API を有効化し、OAuth 同意画面に次のスコープを登録します（読み取り専用・最小限）:
       https://www.googleapis.com/auth/calendar.events.readonly
       （カレンダー一覧の選択が必要な場合のみ）https://www.googleapis.com/auth/calendar.calendarlist.readonly
  4) サーバの環境変数 GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET を設定し、APP_ORIGIN を公開 URL にします。
  注意: スコープの区分（sensitive 等）や、未審査アプリの利用者数上限（100 人）・アプリ審査の要否は
        Google Cloud Console の表示を正としてください（未検証）。

2-2. Microsoft 365 / Outlook（管理者の事前準備）
  1) Microsoft Entra 管理センターでアプリを登録し、リダイレクト URI（Web）に上記と同じ URL を登録します。
  2) API のアクセス許可（委任）: Calendars.ReadBasic と offline_access（予定の本文・添付は読みません）。
  3) 環境変数 MICROSOFT_CLIENT_ID / MICROSOFT_CLIENT_SECRET / MICROSOFT_TENANT（既定 common）を設定します。

2-3. 利用者の操作
  1) 設定 → コネクタ →「カレンダー連携」で「Google カレンダーと接続」または「Microsoft 365 と接続」→ 各社の画面で許可します。
     （サーバーに OAuth クライアントが設定されていない場合はボタンが押せず、その旨が表示されます）
  2) 「接続中のコネクタ」で「予定を確認」を押すと、今後約 30 日分の予定が「予定のプレビュー」として表示されます
     （この時点では会議は作られません）。
  3) 取り込む予定を選び（「すべて選択」も可）、「{n}件を取り込む」を押します。参加者は人（People）として自動登録されます。
     繰り返し予定は 1 つのシリーズにまとまります。
  - 接続したカレンダーは本人専用です。他のメンバーには予定は表示されません。
  - 自動取り込み（autoImport）は既定で OFF です。管理者が明示的に有効にした場合のみ、
    15 分ごとの同期で今後 14 日以内の予定が自動で会議として登録されます。

2-4. iCalendar（.ics）— OAuth 不要
  - 設定 → コネクタ →「ICS（iCalendar）から取り込む」で、予定表の購読 URL（https / webcal）、.ics ファイル、
    または内容の貼り付けから読み込み、「プレビュー」で確認してから「{n}件を取り込む」で取り込みます。
  - Google カレンダーの「iCal 形式の非公開アドレス」は他人に知られると予定が見えてしまう秘密の URL です。
    MeetLedger では暗号化して保存し、画面にはホスト名だけを表示します。漏えいが疑われる場合は Google 側で再発行してください。
  - 対応範囲: 通常の予定、終日予定、タイムゾーン付き予定、毎日・毎週の繰り返し（回数・終了日・除外日・個別変更）。
    毎月・毎年などの複雑な繰り返しは、最初の 1 回だけが「繰り返し未対応」の表示付きで取り込まれます。
  - ファイルサイズ上限は既定 2MB（環境変数 ICS_MAX_BYTES で変更可）。

2-5. カレンダーから保存するデータ
  予定のタイトル・開始/終了日時・主催者と出席者（名前・メールアドレス）のみ。予定の本文（説明欄）は保存しません。

3. 外部への書き込み（Slack / Gmail 下書き / HubSpot / Webhook）
--------------------------------------------------------------------------
3-1. 管理者による登録（設定 → コネクタ →「送信先コネクタ（Slack・Gmail・HubSpot・Webhook）」）
  「種類」を選び、必要な情報を入力して「送信先を追加」を押します。
  - Slack（Incoming Webhook）: Slack で Incoming Webhook を作成し、URL（https://hooks.slack.com/services/...）を登録。
    投稿先チャンネルは Webhook 作成時に固定されます（推奨・権限最小）。「チャンネル名（表示用）」は承認画面の表示用です。
  - Slack（Botトークン）: chat:write スコープの Bot トークン（xoxb-...）と「既定のチャンネル」を登録。Bot を投稿先チャンネルに
    招待してください。チャンネルは送信のたびに変更できます。
  - HubSpot: 非公開アプリのアクセストークン（crm.objects.contacts.write）を登録。送信時に記録先（コンタクト / 会社 / 取引）と
    レコードID を指定し、ノートを追加します。
  - Webhook（任意のURL）: 受信 URL（https）を登録。署名用シークレットは登録直後に 1 回だけ表示されます。
  - Gmail（下書きを作成）: 「Googleアカウントで接続（Gmail下書き）」を押し、Google の画面で許可します
    （接続した Google アカウントの Gmail に下書きを作成するだけで、送信はしません。サーバーに GOOGLE_CLIENT_ID /
    GOOGLE_CLIENT_SECRET が必要です）。
    ※ Gmail の gmail.compose スコープは Google の「制限付き（restricted）スコープ」です。社外の利用者へ公開するには
      Google の OAuth アプリ審査と第三者セキュリティ評価が必要です（費用・期間はお客様負担）。
      審査を避けたい場合は、下書き本文のコピーやメールソフトでの作成をご利用ください。

3-2. 送信の流れ
  1) 会議の「フォローアップ」タブで下書きを「内容を承認」したあと、「送信先」を選び「送信を依頼（承認が必要）」を押すと、
     送信先・本文・送信内容のプレビューが作成されます（未送信）。
  2) 設定 →「外部送信の承認」で、依頼者本人または管理者が内容を確認して「承認して送信」を押すと、1 回だけ送信されます。
     もう一度承認しても再送されません。同じ内容の依頼を重ねて作ることもできません。
  3) 「却下」した依頼は送信されません。送信に失敗した依頼は自動再送されません（内容を確認して新しく依頼してください）。
  - 機密（Confidential）会議の内容を送る場合は、追加の確認が必要です。
  - Slack への投稿では、会議内容に含まれる @channel 等のメンションは無効化されます。

4. 送信 Webhook（イベント通知）
--------------------------------------------------------------------------
  - 管理者が 設定 → コネクタ →「Webhook」で、送信先URL と通知するイベント（会議の準備完了、決定の確定、Action の更新など。
    「すべてのイベント」も可）を入力し「Webhookを追加」で登録します。「テスト送信」で受信を確認できます。
  - 通知内容は ID と最小限の情報のみです（文字起こし・メモ・AI 出力は含みません）。詳細は API トークンで取得してください。
  - 受信 URL の制限（安全のため）:
      ・https のみ（http は開発環境の localhost のみ）
      ・社内ネットワーク / ループバック / クラウドのメタデータアドレス等のプライベートアドレスは不可
        （社内サーバで受信したい場合のみ、環境変数 CONNECTOR_ALLOW_PRIVATE_NETWORKS=1 で明示的に許可）
      ・リダイレクトには追従しません
  - 署名の検証: ヘッダ X-MeetLedger-Signature の値 "t=<時刻>,v1=<署名>" について、
      HMAC-SHA256(シークレット, "<時刻>.<受信した本文そのまま>") の 16 進文字列が v1 と一致し、
      時刻が 5 分以内であることを確認してください（docs/CONNECTORS.md §4 にコード例）。
  - 受信側が失敗（2xx 以外）した場合は最大 5 回まで間隔を空けて再送します。最新の送信結果は同じ画面に表示されます。

--------------------------------------------------------------------------
5. API トークン
--------------------------------------------------------------------------
  - 設定 →「APIトークン・MCP」で「用途の名前」「有効期限」を入力し「トークンを作成」を押します。トークンは作成時に 1 回だけ
    表示されます（再表示不可・紛失時は無効にして再作成）。
  - 権限: 標準は読み取りのみ。「書き込みを許可（write）」をオンにすると書き込みもできます。トークンは 1 つのワークスペース専用で、
    管理者操作・外部送信の承認はできません。
  - 不要になったトークンはすぐに「無効にする」を押してください。無効化は即時に反映されます。

6. ChatGPT / Codex との連携（MCP）
--------------------------------------------------------------------------
  - MeetLedger は MCP サーバ（https://<ドメイン>/mcp）を提供します。AI アシスタントから会議検索、決定事項・自分の Action・
    約束・未解決の質問の参照、会議の作成、レビュー、Follow-up 下書きの作成、次回会議の準備ができます。
  - 書き込み系の操作は必ず 2 段階です（1 回目はプレビューだけ、利用者が承認した後の 2 回目で実行）。
    メール・Slack などへの「送信」は AI アシスタントからは行えません。
  - アクセス範囲は API トークンを作った利用者と同じです（非公開会議は作成者以外に見えません）。
  - Codex: ~/.codex/config.toml に次のように設定し、環境変数 MEETLEDGER_TOKEN に API トークンを設定します。
        [mcp_servers.meetledger]
        url = "https://<ドメイン>/mcp"
        bearer_token_env_var = "MEETLEDGER_TOKEN"
        default_tools_approval_mode = "writes"
  - ChatGPT: 公開プラグインとしての配布や開発者モードでの接続には OAuth 2.1 認証が必要ですが、
    本バージョンは未対応です（今後対応予定）。ChatGPT からの接続は現時点で未検証・未対応です。
    なお公開配布にはプライバシーポリシー URL（HTTPS）の掲載が必須です。
  - 詳細は docs/MCP_PLUGIN.md をご覧ください。

7. セキュリティとプライバシー
--------------------------------------------------------------------------
  - 連携サービスのトークン、Webhook の URL・シークレット、非公開 ICS URL は暗号化（AES-256-GCM）して保存します。
    暗号鍵は環境変数 MASTER_KEY から派生します。MASTER_KEY を変更すると全ての連携の再接続が必要です。
  - 外部サービスとの通信は記録（宛先ホスト・目的・サイズ・結果のみ。内容は記録しません）されます。
  - ログに認可コード・トークン・本文は出力しません。
  - 本製品は法的助言を提供するものではありません。外部サービスへの個人データ送信に関する同意・契約は、お客様の責任でご確認ください。

8. よくあるエラー
--------------------------------------------------------------------------
  connector_not_configured   … サーバに OAuth クライアント（環境変数）が設定されていません。
  invalid_state              … 接続画面の有効期限（10 分）切れ、または別のブラウザ/別ユーザーで完了しようとしました。最初からやり直してください。
  scope_not_granted          … 許可画面で必要な権限のチェックが外されました。もう一度接続し、権限を許可してください。
  reauth_required            … 連携の許可が失効しました（パスワード変更・権限取り消し等）。再接続してください。
  unsafe_url / unresolvable_host … URL が https でない、社内向けアドレスを指している、またはホスト名を解決できません。
  confidential_ack_required  … 機密会議の内容を外部へ送るには追加確認が必要です。
  insufficient_scope         … 読み取り専用トークンで書き込み操作をしようとしました。
  invalid_confirmation       … AI アシスタントの確認トークンが期限切れ（10 分）・使用済み・内容不一致です。もう一度プレビューから行ってください。

9. 既知の制限・未検証事項
--------------------------------------------------------------------------
  - Google / Microsoft / Slack / HubSpot / Gmail / ChatGPT / Codex の実環境での接続は未検証です。
  - ChatGPT 接続用の OAuth 2.1 は未対応です。
  - ICS の毎月・毎年の繰り返し等は未対応（最初の 1 回のみ取り込み）。
  - Google の複数カレンダーの選択画面は未対応です（1 つのカレンダーを指定可能）。
  - 送信 Webhook の一部イベントは今後のバージョンで順次通知対象になります。
