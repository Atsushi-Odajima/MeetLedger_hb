MeetLedger はじめにお読みください
====================================================
対象バージョン: MeetLedger 1.0（2026-10-02 時点）

「会議しただけで終わらせない。」
MeetLedger は、会議の「決まったこと」「やること」「約束」「答えが出なかった問い」を記録し、
次の会議まで追いかけるためのツールです。録音・文字起こし・要約だけで終わらず、確認・フォローアップ・
次回の準備までを 1 か所で行えます。

※ 文中の画面の名前・ボタン名は、Web アプリの日本語表示（2026-10-02 時点）に合わせています。
  版によって表記が変わる場合があります。
※ 「（未検証）」と書いた手順・機能は、開発環境で実際に確認できていないものです。本番利用の前に、
  お客様の環境で必ず動作を確認してください。


1. MeetLedger でできること
----------------------------------------------------

  - 会議（Meeting）の作成、手動メモ、録音、録音ファイルのアップロード、文字起こしファイルの取り込み
  - 文字起こし（標準はサーバー内で処理し、外部に音声を送りません）
  - 要約と、決まったこと・やること・約束・未解決の問いの「候補」の抽出
  - 確認待ち（Review Inbox）で候補を人が確認し、承認したものだけを台帳（Ledger）に確定
  - フォローアップ文面の下書き（自動送信はしません）
  - 次回の会議のための「ブリーフ（Brief）」と「アジェンダ（Agenda）」の準備
  - 過去の会議の検索と、記録にもとづく AI への質問（Ask）
  - スマートフォンからの利用（PWA）、デスクトップアプリでの相手側の音声の録音

  MeetLedger は「AI が勝手に決めない」ことを大切にしています。
    - AI が見つけた内容は、人が承認するまで「候補」のままです。
    - 聞き取れなかった部分を AI が推測で埋めることはありません。
    - 録音の前に、参加者へ伝えたことの記録が必要です（秘密録音の機能はありません）。
    - フォローアップや外部サービスへの送信は、自動では行いません。
    - 「自分だけ（Private）」の会議は作成者しか見られません（管理者も見られません）。


2. 構成
----------------------------------------------------

  (1) サーバー（必須）     お客様のサーバーで動かします（Docker または Node.js）。
                            Web アプリの画面も、このサーバーから配信されます。
  (2) データベース（必須） PostgreSQL 16
  (3) Web アプリ / PWA     パソコン・スマートフォンのブラウザで使います（インストール不要）。
  (4) デスクトップアプリ   任意。Windows / macOS で、オンライン会議の相手側の音声（システム音声）も
      （MeetLedger Desktop） 録音したい場合に使います。詳しくは「録音と同意.txt」をご覧ください。
  (5) 連携（任意）         カレンダー、Slack、Webhook、API トークン、ChatGPT / Codex（MCP）。
                            「Connector.txt」をご覧ください。

  初期設定では、文字起こしも AI 処理もサーバーの中だけで行います（ローカル優先）。
  外部の AI サービスを使うには、サーバーの設定と Workspace 管理者の許可の両方が必要です
  （「Local-Privacy Mode.txt」）。


3. 動作環境
----------------------------------------------------

  サーバー
    - Node.js 22.12 以上（Docker を使う場合はイメージに含まれます）
    - PostgreSQL 16
    - ffmpeg / ffprobe（音声の変換に使います。Docker イメージには含まれます）
    - ディスク: 文字起こしモデル約 200MB、処理中の一時ファイル（会議 1 時間あたり約 115MB。処理後に削除）、
      音声・データの保存領域
    - CPU: ローカル文字起こしは CPU を使います。開発時の実測（4 vCPU / メモリ 15GB の環境）では、
      1 時間の会議の処理におよそ 7〜13 分かかりました（「文字起こし.txt」）。最小要件は未測定です。
    - 公開する場合は HTTPS（TLS）が必要です。ブラウザでの録音（マイク）は HTTPS でないと使えません
      （例外: 同じパソコン上の http://localhost）。

  ブラウザ（Web アプリ / PWA）
    - パソコン: Chrome / Edge（タブの音声も録音できる場合があります）、Safari、Firefox（マイクのみ）
    - スマートフォン: iPhone / iPad（Safari）、Android（Chrome）。録音はマイクのみです（「スマホ-PWA.txt」）
    - 自動テストは Chromium で実施しています（スマートフォンは iPhone 15 / Pixel 8 の画面を Chromium で模擬）。
      Safari（WebKit）・Firefox・スマートフォン実機での確認は未検証です。

  デスクトップアプリ（任意）
    - Windows 10 / 11（x64）、macOS（相手側の音声の録音は macOS 14.2 以降）
    - Windows / macOS の実機での相手側音声の録音は未検証です（「注意事項.txt」）。


4. インストール方法 A: Docker compose（未検証）
----------------------------------------------------

  付属の deploy/docker-compose.yml は「例」です。開発環境に Docker がなかったため、
  この手順は実際には確認できていません（未検証）。本番前に必ず試験環境でお試しください。

  1) 設定ファイルを作ります（MeetLedger のフォルダで実行）。

       cp .env.example .env

  2) .env を編集し、少なくとも次を設定します。
       APP_ORIGIN                    利用者がブラウザで開く URL（例: https://meetledger.example.co.jp）
       SESSION_SECRET                32 文字以上のランダムな値（例: openssl rand -base64 48 の出力）
       MASTER_KEY                    32 バイトの鍵（openssl rand -base64 32 の出力）
       POSTGRES_SUPERUSER_PASSWORD   データベース管理用のパスワード（docker compose 用）
       APP_DB_PASSWORD               アプリ用データベースのパスワード（docker compose 用）

     ※ MASTER_KEY は音声ファイルなどの暗号化に使う大切な鍵です。作ったらすぐに、別の安全な場所へ
       控えを保管してください。失うと暗号化されたデータは二度と読めません（「Backup-Restore.txt」）。
     ※ NODE_ENV=production のまま SESSION_SECRET / MASTER_KEY を空にすると、サーバーは起動しません。

  3) 起動します。

       cd deploy
       docker compose --env-file ../.env up -d

     ※ --env-file ../.env は必ず付けてください。compose ファイル内の ${POSTGRES_SUPERUSER_PASSWORD} などを
       ../.env から読み込むためです。初回はイメージの作成（ビルド）が行われます。新しいバージョンに
       入れ替えたときは up -d --build で作り直してください。

  4) 文字起こしモデルを入れます（6 章）。
  5) サーバーは 127.0.0.1:8787 で待ち受けます。外部に公開するときは、Caddy や nginx などの
     HTTPS 対応のリバースプロキシを前に置き、.env の COOKIE_SECURE=true / TRUST_PROXY=true のまま
     使ってください。大きな録音ファイルを受け付けられるよう、プロキシ側のアップロード上限も
     MAX_UPLOAD_MB（既定 1024MB）に合わせてください。
  6) 動作確認: https://<あなたのドメイン>/api/health が {"ok":true} を返せば起動しています。


5. インストール方法 B: Node.js で直接動かす
----------------------------------------------------

  1) 必要なもの（Node.js 22.12 以上、PostgreSQL 16、ffmpeg / ffprobe）をインストールします。

  2) データベースを用意します。アプリ用のユーザーは「スーパーユーザーではない」ユーザーにしてください
     （データの分離に、PostgreSQL の行レベルセキュリティを使っているためです）。例:

       CREATE ROLE meetledger LOGIN PASSWORD '（パスワード）' NOSUPERUSER NOBYPASSRLS NOCREATEROLE;
       CREATE DATABASE meetledger OWNER meetledger;

  3) MeetLedger のフォルダで、部品のインストールとビルドを行います。

       npm ci
       npm run build

  4) 設定ファイルを作ります: cp .env.example .env として、4 章の 2) と同じ項目に加えて
       DATABASE_URL     postgres://meetledger:（パスワード）@127.0.0.1:5432/meetledger
       STORAGE_DIR      音声などの保存先（書き込みできるフォルダ）
       TMP_DIR          一時ファイルの置き場所
       LOCAL_ASR_MODEL_DIR  文字起こしモデルのフォルダ（絶対パス。6 章）
     を設定します。

  5) 起動します（データベースの準備（マイグレーション）は起動時に自動で行われます）。

       cd apps/server
       node --env-file=../../.env dist/index.js

     サーバーは既定で 127.0.0.1:8787 で待ち受けます。公開時は 4 章の 5) と同じく HTTPS の
     リバースプロキシを前に置いてください。
     ※ 同じパソコンで http://localhost:8787 を開いて試す場合は、APP_ORIGIN=http://localhost:8787、
       COOKIE_SECURE=false にしてください（APP_ORIGIN とブラウザの URL が違うと、操作が拒否されます）。

  6) コマンドでの管理（バックアップ、オーナーの作成など）は docs/OPERATIONS.md をご覧ください。


6. 文字起こしモデルの準備
----------------------------------------------------

  ローカル文字起こしに使うモデルは、製品に同梱していません。管理者が次のコマンドで取得します
  （インターネット接続が必要です。サーバーが自動でダウンロードすることはありません）。

    bash scripts/download-models.sh                  文字起こし＋話者分離（誰が話したかの区別）
    bash scripts/download-models.sh sense-voice      文字起こしだけ

  - 保存先は LOCAL_ASR_MODEL_DIR（未設定ならリポジトリの models フォルダ）です。
    例: LOCAL_ASR_MODEL_DIR=/srv/meetledger/models bash scripts/download-models.sh
  - このコマンドの実行には、MeetLedger のフォルダで npm install（または npm ci）を済ませておく必要があります。
  - Docker の場合（未検証）: ホストでダウンロードしたモデルを、コンテナの /models にコピーします。
      cd deploy
      docker compose --env-file ../.env cp ../models/. app:/models/
    または docker-compose.yml の「models:/models」を、ホストのフォルダ（例: /srv/meetledger/models:/models:ro）
    に書き換えて使います。
  - モデルのライセンスと表示が必要な文言は、「設定」→「このアプリについて・ライセンス」の
    「ローカル文字起こしに使うAIモデル」と「THIRD_PARTY_NOTICES.txt」1 章に記載しています。
    話者の声の特徴を数値にするモデル（3D-Speaker CAM++）は、商用利用のライセンスが未確認です。
    販売・商用利用の前に法務確認が必要です（文字起こしだけなら sense-voice のみで動きます）。
  - モデルが無いまま録音をアップロードすると、「処理の状況」に「ローカル文字起こしを実行できません」と
    表示されます。モデルを入れたあと「文字起こしをやり直す」を押してください。


7. 初回セットアップ
----------------------------------------------------

  1) ブラウザで APP_ORIGIN の URL を開きます。初回は「MeetLedger のセットアップ」画面が表示されます。
  2) 次を入力します。
       名前 / メールアドレス / パスワード（10 文字以上）
       組織名（会社名・チーム名・屋号など）
       最初のWorkspace名（既定は「Main」）
  3) 「サンプルWorkspace（架空データ）も作成する」は、操作を試したい場合にオンのままにします。
  4) 「セットアップを完了」を押すと、あなたが最初の管理者（オーナー（Owner））になります。

  画面に「初期設定はローカル優先です」と表示されるとおり、管理者が許可するまで、文字起こしと AI 処理は
  サーバーの中だけで行われます。

  ほかのメンバーを招待する
  1) 左のメニュー「設定」→「招待」を開きます。
  2) メールアドレスと権限（管理者 / メンバー / 閲覧者）を選び、「招待リンクを作成」を押します。
  3) 表示されたリンクを、安全な方法で本人に伝えてください（有効期限 7 日）。
     MeetLedger は招待メールを自動送信しません。
  ※ 新規登録（サインアップ）は既定で無効です（ALLOW_SIGNUP=false）。メンバーは招待で追加します。

  権限の目安: オーナー / 管理者 = 設定とメンバー管理、メンバー = 記録と編集、閲覧者 = 閲覧のみ。
  「自分だけ（Private）」の会議は、管理者にも見えません。


8. サンプル Workspace（架空データ）
----------------------------------------------------

  - 架空の会議（定例の「Weekly Product」、確認待ちの「Client Review」、自分だけの「1on1」など）と、
    決まったこと・やること・約束が入っています。登場する人物・会社はすべて架空です。
  - 実際のデータとは別の組織（Sample Organization（架空データ））に作られるため、本番の会議一覧・
    検索・AI への質問には表示されません。
  - セットアップ時に作らなかった場合は、画面左上の Workspace 名のメニュー →「サンプルWorkspaceを作成」
    から作れます（サーバーの設定 SAMPLE_WORKSPACE=true のとき）。
  - サンプル Workspace では通知は送られません。
  - 不要になったサンプルの削除は、現在は運用者によるデータベース操作が必要です（docs/RETENTION_DELETE.md §6）。


9. 画面の見かた
----------------------------------------------------

  左のメニュー（スマートフォンでは下のメニュー＋「その他」）
    ダッシュボード          今日の会議、確認待ち、自分のやること・約束、期限を過ぎたもの など
    Meeting                 会議の一覧と「新しいMeeting」
    確認待ち（Review Inbox） AI や取り込みで見つかった候補の確認
    台帳（Ledger）          決まったこと・やること・約束・未解決の問いの一覧
    検索 / AIに質問（Ask） / 記憶（Memory）
    人（People） / プロジェクト / 定例（Series）
    通知 / 設定

  画面右上: 未同期の変更、通知、表示言語の切り替え（日本語 / English）、アカウントメニュー

  「設定」の中のメニュー
    プライバシー / メンバーと権限 / 招待 / コネクタ / 外部送信の承認 / APIトークン・MCP / データ / アカウント /
    このアプリについて・ライセンス（バージョン、AIモデルとフォントのライセンス、第三者ソフトウェアの表示）

  一覧の見かた
    - 件数の多い一覧は途中までを表示し、下の「もっと見る」で続きを読み込みます（全体の件数も表示されます）。
    - ダッシュボードの各欄は上位 10 件までを表示します。続きは「すべて見る」から開きます。
      件数がとても多い場合は「1000+」のように表示されます。

11. 困ったときは
----------------------------------------------------

  - 画面が開かない: サーバーが起動しているか、/api/health を確認してください。
  - ログインやボタン操作がエラーになる: .env の APP_ORIGIN が、ブラウザで開いている URL と完全に
    一致しているか確認してください（http / https、ポート番号を含む）。
  - 録音ボタンが押せない: HTTPS で開いているか、参加者への通知を記録したか、会議の文字起こし設定が
    「文字起こししない（メモのみ）」になっていないかを確認してください。
  - 文字起こしが失敗する: 6 章のモデルが入っているか、「記録（Capture）」タブの「処理の状況」を確認してください。
  - 運用（バックアップ、監視、アップグレード）: docs/OPERATIONS.md
